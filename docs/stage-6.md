Старая APK собрана из Git, это не обновление опубликованной версии из Google Play; перенос старого UI-стека не обещается.
- **Настоящий Photo Picker после завершения процесса.** В галерею эмулятора добавлена тестовая копия снимка виртуальной камеры. Открыт системный выбор фото, приложение отправлено в фон, его процесс завершён через `run-as ... kill -9` (обычный `am kill` не завершил процесс). Проверено отсутствие прежнего PID. Возврат через Recents восстановил задачу с другим PID; выбор фото успешно вернулся в приложение, создал приватную `.img`-копию, закрыл диалог и обновил поле. Это завершение настоящего процесса, но не воспроизведение нехватки памяти ОС.
- **Настоящая камера после завершения процесса.** При открытой внешней камере завершён процесс Tokens. После съёмки и подтверждения приложение запустилось с новым PID, сохранило JPEG и показало фото без повторного запуска камеры. Камера — приложение эмулятора с виртуальным источником изображения, не физическая камера производителя телефона.
- **Отмена камеры и галереи.** Back из обоих внешних приложений возвращает диалог выбора. SHA-256 сохранённой настройки и всех прежних приватных фото не изменились; незавершённый снимок камеры удалён. Диалог остаётся доступен для нового выбора.

- Шаблонный `tokens_feature/impl/ExampleInstrumentedTest`, ранее исключавшийся фильтром, ожидал старый `com.cerebus.tokens.presentation`. Воспроизведено на API 34; ожидание исправлено на действующий `com.cerebus.tokens.feature.tokens_feature.test`. Полный Android-прогон на API 34 и debug-компиляция прошли. Коммит `0c76dba`.
- На чистом телефоне API 36 `photoLeavesRoomForAllTokensAndFollowsOnlySavedSetting` зависел от плотности/системных отступов host Activity: в отведённой области фото могло скрыться по правильному правилу приоритета жетонов. Тест получил явную LocalDensity и consumeWindowInsets, как соседние тесты геометрии; production-код не менялся. Отдельный сценарий скрытия фото в тесном окне сохранён. Все восемь TokensScreenTest, TokenBoardGeometryTest и debug-компиляция прошли. Коммит `9a5d50f`.
- На исходном телефонном AVD установка тестовой APK жетонов остановилась с `INSTALL_FAILED_INSUFFICIENT_STORAGE` (свободно около 369 MB). Чужие приложения и данные не удалялись. Для полного прогона создаются отдельные временные AVD/data, пользовательские AVD не очищаются.

## Как повторить

- Для полного Android-прогона: `ANDROID_SERIAL=<serial> ./gradlew connectedDebugAndroidTest :app:compileDebugKotlin --continue`. Фильтры классов не передавать: они скрывали устаревшие шаблонные тесты. Для нескольких выбранных AVD можно указать serial через запятую.
- Свежий JVM-прогон: `./gradlew testDebugUnitTest :app:compileDebugKotlin --rerun-tasks`. Проверять не только успешную конфигурацию Gradle, но и exit code и XML-отчёты тестов.
- Для системного сценария завершения процесса использовать обычную debug APK, не тестовый host: открыть диалог/внешнее приложение, сохранить Activity в фоне, получить PID, завершить только процесс Tokens и проверить его отсутствие, восстановить существующую задачу через Recents. Не использовать `force-stop` или очистку данных вместо завершения процесса: это другой сценарий.
- Для обновления обе APK должны иметь одинаковые applicationId и debug-подпись. Устанавливать через `adb install -r`, без uninstall/clear. До и после сравнить приватные сохранения и собственное фото через `run-as` и SHA-256, затем проверить UI. Использовать только специально созданные тестовые данные.
- Для фото проверить не только появление изображения, но и отмену с прежним фото, запись приватной копии, отсутствие повторного запуска внешней Activity и возможность нового выбора.
