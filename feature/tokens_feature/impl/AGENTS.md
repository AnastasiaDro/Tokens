# Жетоны и настройки

- Читать корневой `AGENTS.md`. Модуль содержит оба экрана, данные, эффекты победы и Koin-модуль. Внешний вход — TokensMediator из api; фото открывается через ReinforcementPhotoMediator, без зависимости на его impl.
- При изменении количества N → M с K отмеченными: при M=N ничего не менять; при увеличении сохранить отметки и добавить пустые; при уменьшении полностью заполненного поля отметить все M, иначе оставить min(K, M−1) отметок.
- При уменьшении сохранять позиции оставшихся отметок, переносить отметки удаляемых жетонов в свободные позиции слева направо; лишние снимать справа налево. Уменьшение незавершённого поля до одного жетона даёт 0/1, завершённого — 1/1.
- Смена количества, восстановление и возвращение на экран не запускают победу. Победа запускается при переходе незавершённого поля в завершённое после отметки пользователем.
- Список жетонов и сохранённый прогресс должны согласовываться. Повторная отметка/снятие одной и той же отметки не меняют счётчик повторно. Некорректные старые сохранения нормализовать без выхода за границы списка.
- Рабочий диапазон — 1–20 жетонов; UI и валидация DataStore используют общий MAX_TOKEN_COUNT. Историческая миграция SharedPreferences сохраняет отдельный предел LEGACY_MAX_TOKENS=10; не расширять его вслед за рабочим лимитом.
- Все жетоны одинакового размера и одновременно видны без прокрутки поля. При 20 цель — четыре ряда по пять на телефоне и два по десять в широком высоком окне. В тесном окне сначала сокращать промежутки, затем менять сетку ради большего диаметра. Фото не уменьшает диаметр жетонов: размещается сбоку/снизу, а при нехватке места скрывается; действие фото остаётся в меню при включённом подкреплении. В портретном окне шириной от 600 dp фото размещается над жетонами, по горизонтальному центру, размером до 300 dp (вдвое больше телефонного) с отступом 16 dp. Поле сохраняет полную доступную высоту и независимый вертикальный центр; при нехватке места уменьшается фото. Не центрировать фото и поле вместе в Column.
- Звук и анимация независимы по настройкам. Не допускать конкурирующих таймеров победы; останавливать эффекты при уходе с экрана и освобождать медиаресурсы.
- Подписки эффектов привязывать к lifecycle соответствующего NavBackStackEntry. Не воспроизводить звук из render/onDraw или при повторном получении того же состояния.
- Целевой TokenState содержит ID, форму, цвет и отметку; по согласованию форма пока только круг, без настройки выбора формы.
- Compose-компонент `presentation/tokens_screen/Token.kt` получает TokenState без локальной копии checked/color и только передаёт нажатие родителю. При подключении поля использовать key(state.id) и передавать ID в обработчик ViewModel; не ключевать жетоны по позиции. `enabled` отвечает только за доступность взаимодействия, не за отметку.
- Жетон использует ограничения родителя для размера; расчёт общего размера поля выполняется на уровне экрана. При изменении компонента запускать Compose-тесты `presentation.tokens_screen.TokenTest` (семантика, клики, цвета, перестановка и размеры).
- TokensMediatorImpl регистрирует Compose-маршруты; TokensLifecycle связывает lifecycle back-stack entry со звуком и ViewModel. TokensRoute собирает StateFlow, TokensScreen получает состояние и единый onAction. TokensViewModel разбирает TokensAction через when, обновляет state чистыми extension-функциями из object TokensReducer и вызывает методы TokensNavigator, полученного через DI. TokensRoute создаёт и освобождает привязку navigator к обработчику переходов. Следовать разделу «Архитектура экранов» корневого AGENTS.md.
- TokenBoard и отдельные UI-компоненты могут сохранять локальные callbacks. tokenBoardGeometry ограничивает общий размер жетонов шириной и высотой; поле не прокручивается. Меню остаётся доступным, свайп справа налево длиннее трети поля очищает его, обычный клик только передаёт стабильный ID.
- WinSoundPlayer подключён через локальный WinSoundOutput (factory в impl) для тестирования реального Compose NavHost; звук запускается только на новом celebrationId из STARTED-подписки. Остановка/освобождение обязательны при ON_STOP и выходе композиции; navigation и фон не должны оставлять плеер работающим. Не переносить play в Compose render.
- WinCelebration использует lottie-compose и Lottie единой версии 6.6.7. Три фейерверка ключуются celebrationId, задержки 0/500/800 мс относятся только к последовательности отображения. Таймер окончания победы единственный, во ViewModel. ON_STOP снимает анимации и запрещает повтор старого ID при возобновлении со старым Compose-снимком.
- Фото отображается общим асинхронным PhotoPreview из core:ui; состояние ошибки предлагает повторный выбор, сохранённый URI не обнуляется. Размер области фото по-прежнему определяется геометрией поля, загрузчик не меняет размер жетонов. Наличие камеры не влияет на подкрепление: и показ фото, и переключатель настроек используют только ReinforcementSettings.enabled; галерея доступна без камеры. AndroidView/ImageView, TokenView, CustomStyledSwitch, старые layout/menu XML и SwipeParser удалены; не возвращать параллельную View-реализацию Compose-экранов.
- Для поля/эффектов запускать TokenBoardGeometryTest, TokensViewModelTest, TokensScreenTest, WinCelebrationTest и TokensFlowTest. Последний использует изолированные репозитории и подменённый звук; отдельный smoke-тест проверяет настоящий MediaPlayer в foreground. Поддерживаются обе ориентации: проверять поворот с прогрессом/черновиком и восстановление, обычное/тесное окно, крупный шрифт и фото. Изменять в тестах конфигурацию Activity/Compose, не глобальные настройки устройства.
- Состояние хранится в tokens.json и effects.json через единичные DataStore-репозитории из DI. SharedPreferences читать только при миграции; не возвращать синхронные getter-ы, ручной refresh или отдельный UiCache.
- TokensViewModel и SettingsViewModel наблюдают общие потоки, экраны получают единый StateFlow. Редьюсеры чистые; диалоги количества/цвета имеют собственные ViewModel и закрываются только после подтверждённой записи.
- Настройки уже используют SettingsRoute/SettingsScreen и нейтральный фон общей темы (градиент не сохранять). Mediator регистрирует переходы и передаёт callback внешних ссылок, Route подписывается через collectAsStateWithLifecycle, Screen получает состояние и callbacks.
- Диалог количества использует SelectTokensNumberUiState и чистый reduceTokensNumber. Черновик хранить через SavedStateHandle, созданный из CreationExtras back-stack entry и переданный в Koin; повторная инициализация не сбрасывает его. Запись только по подтверждению, закрытие только после SAVED; во время SAVING блокировать также Back/касание вне диалога через NavigationDialog с проверкой актуального состояния VM. После восстановления процесса незавершённая запись не запускается автоматически.
- Диалоги количества и цвета не должны показывать временную надпись «Сохранение…» или менять размеры/положение содержимого при переходе в SAVING. На время записи блокировать действия, сохраняя стабильную геометрию; иной индикатор добавлять только по явному запросу пользователя и без переразметки диалога.
- Диалог цвета использует SelectColorScreen, ColorUiState и reduceColor; черновик и завершённый успех хранятся через SavedStateHandle. Поток репозитория инициализирует только отсутствующий черновик, дальнейшие эмиссии его не сбрасывают. При ошибке чтения/загрузке нельзя сохранять даже восстановленный черновик; ошибка записи сохраняет выбор для повтора. Действуют те же блокировки SAVING и правила восстановления, что у количества.
- colorpicker-compose 1.1.2 подключён только в impl. Перед обновлением проверять Kotlin/Compose в транзитивных зависимостях. Принимать только пользовательские ColorEnvelope (fromUser); служебная инициализация не меняет черновик. HsvColorPicker создаётся только после загрузки, с активным controller; не инициализировать disabled controller с нулевыми координатами. Яркость восстанавливать отдельно через BrightnessSlider, initialColor стабилен на время жизни picker.
- Для цвета запускать SelectColorViewModelTest, ColorPickerTest и SettingsFlowTest. Тестовый host использует тот же mediator и rememberNavController, что приложение. Для проверки цвета в отдельном Compose Dialog использовать снимок настоящего окна, сохраняя проверки черновика, поворота и повторного открытия.
- Для изменений настроек/диалога выполнять SettingsScreenTest и SettingsFlowTest: изолированный тестовый host использует реальный граф/DI с подменёнными репозиториями, не пользовательские сохранения. Fragment/Safe Args, Parcelable аргументы и ComposeView-ID удалены. ViewModel принадлежат отдельным NavBackStackEntry через navigationViewModel; при повторном открытии диалога должен создаваться новый черновик.
- Клики выполняются по стабильному ID внутри updateData. Ошибка чтения не означает пустое поле; ошибка записи не означает успех. При добавлении полей формата учитывать уже сохранённые документы и версию схемы.
- Проверять правила количества, позиции, идемпотентность и восстановление unit-тестами; таймеры — с виртуальным временем; Android-плеер и lifecycle — на устройстве/эмуляторе. Основная команда: `:feature:tokens_feature:impl:testDebugUnitTest`.
