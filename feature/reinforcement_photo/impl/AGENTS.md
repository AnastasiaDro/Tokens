# Фото подкрепления

- Читать корневой `AGENTS.md`. Модуль отвечает за выбор фото, съёмку и результат операции.
- Photo Picker работает без READ_MEDIA_IMAGES/READ_EXTERNAL_STORAGE; TakePicture передаёт FileProvider URI приватного файла внешней камере без CAMERA/WRITE_EXTERNAL_STORAGE. Не возвращать широкие разрешения ради точечного выбора фото. CAMERA не deprecated, но прямого доступа к камере в приложении нет.
- Сохранять URI ожидающей съёмки при пересоздании/уничтожении процесса. Отмену операции не считать успешным выбором фото.
- AndroidPhotoFiles копирует выбранное фото в filesDir/reinforcement, проверяет декодируемость и выдаёт FileProvider URI. Временный persistable grant запрашивается по возможности для прерванного импорта; после записи приватной копии освобождается. Обрабатывать недоступное изображение и отсутствие приложения камеры.
- Удалять после отмены только временный файл, созданный текущей операцией. Не удалять пользовательское фото из галереи.
- Не запрещать выбор фото и показ подкрепления из-за отсутствия камеры: галерея остаётся доступной.
- Вход извне — ReinforcementPhotoMediator из api, реализация и Koin-модуль принадлежат impl. Не ссылаться на классы фичи жетонов.
- Сейчас фото сохраняется напрямую через общий ReinforcementRepository. Его Flow обновляет все потребители без nav-result refresh; PhotoUiState хранит загрузку, ошибку и подтверждение записи до появления подписчика.
- Ожидающий источник, URI камеры, выбранный/подготовленный URI и завершение записи хранятся в SavedStateHandle. Команда запуска — состояние с consumeLaunch перед launcher.launch, не одноразовый SharedFlow. После восстановления незавершённая запись требует явного повтора; результат, пришедший до первого чтения, ожидает загрузку. При отмене не удалять уже сохранённый URI, даже если процесс завершился между записью и подтверждением успеха.
- Старые MediaStore/SAF URI сохраняются без переписывания; недоступный старый URI не обнулять. Оригиналы галереи и ранее сохранённые фото не удалять. discard принимает только собственный authority, путь reinforcement_photos и имя приватного файла.
- Проверять отмену, успешный результат, восстановление и разные версии Android; минимальная компиляция — `:feature:reinforcement_photo:impl:compileDebugKotlin`.
- PhotoDestinationContent собирает StateFlow, PhotoScreen получает состояние и callbacks. В тесном окне содержимое диалога прокручивается, но кнопка закрытия остаётся доступна в закреплённой шапке; действия выбора источника расположены вертикально для крупного шрифта. Предпросмотр — общий PhotoPreview из core:ui. ViewBinding, viewbindingDelegate, CardView и XML-вёрстка фото удалены.
- PhotoDestination — Compose Navigation dialog. PhotoDestinationContent регистрирует rememberLauncherForActivityResult без условного создания, запускает источники/закрытие из STARTED-подписки. NavigationDialog проверяет актуальное VM-состояние при Back/касании снаружи и вызывает cancel для очистки. ViewModel и SavedStateHandle принадлежат NavBackStackEntry; Fragment-адаптер удалён.
- PhotoLayoutTest проверяет крупный шрифт, тесное окно, поворот/recreation и контракты через настоящие Compose NavHost/ActivityResultRegistry с перехватом внешних Intent. Реальная камера и галерея не запускаются, данные изолированы. PhotoScreenTest проверяет блокировки и ошибки, PhotoFilesTest — настоящие приватные файлы; эти наборы дополняют, а не заменяют проверку внешних приложений на устройстве.
